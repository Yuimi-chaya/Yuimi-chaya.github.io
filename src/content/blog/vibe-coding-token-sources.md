开始用 AI 写项目以后,你很快就会发现 token 不是一个抽象的数字.它是一次又一次的读代码、改代码、失败重试,也是你刚要开始下一轮任务时突然看见"额度不足"的那个瞬间.

先说在前面,这篇文章不会推荐任何第三方中转站,也不会指着某一家官方的某个服务说"买它就对了".我想聊的是这些 token 究竟从哪里来,不同买法解决了什么问题,以及掏钱之前有哪些账不能只看宣传图.

## 官渠好懂,但不一定好买

走官方渠道通常就两条路:买一个有周期额度的订阅套餐,或者开 API 按实际用量付费.国内模型的购买入口和支付方式对不少人来说比较直接,选好适合自己的套餐或 API,照着平台说明开通就能用.换成 GPT、Claude、Grok 等海外服务,支付卡、身份或地区要求、网络连通性都可能成为门槛,每家的规则也不一样;这不是换个客户端就能解决的事.

很多时候,**只要你用得足够多,订阅摊下来确实比按官方 API 单价逐笔结算便宜.** 但它卖的是一段时间内可用的额度,不是往账户里存了一笔永远花不完的钱.你得留意到期日、周期额度、滚动窗口和触发限额后的恢复时间;用得少时怕浪费,用得多时又怕下一轮任务被限额挡住.那种明明付了钱,却总觉得有人轻轻揪着小辫子催自己赶紧用的感觉,我想不少人都懂.

API 的好处是按量算账,什么时候用、用多少都比较直观,不用跟着订阅的周期窗口安排自己什么时候开工.只是大任务跑起来,账单也可能比想象中长得快.

## 中转站填的是什么空

这就到了中转站出场的地方.你给中转站付款,拿到它提供的接口和密钥,由它去连接上游模型;对使用者而言,它可能同时解决支付、连通性和多模型接入的问题,用起来则更像是往站内充一笔余额,需要时再慢慢扣.

其中一种做法,是把订阅账号的使用能力反代成供客户端调用的接口,再用号池轮转分摊请求和限额.有人用,账号和成本又转得过来,它就能一直跑下去.也有中转走正式 API 或混合多种上游,所以买之前最好弄清楚自己买到的究竟是哪一种.

这种站内余额比订阅的周期额度更像是可以慢慢花的钱,但中转站说没就可能没了.所以我自己的原则很简单:**用多少充多少**,不要因为一个夸张的折扣就把未来半年的预算先压进去.

还有隐私这笔账.请求经过中转站,对方就可能接触你的提示词、代码和文件.个人娱乐项目我不会太焦虑,但公司的私有仓库、涉及自己或别人的敏感信息,我就不建议交给一个连上游和数据怎么处理都说不清的站点.

不过开源或官渠也不是隐私保险箱,像 [ZCode 曾被发现打包工作区并发起上传](https://blog.ferstar.org/en/posts/zcode-silent-workspace-snapshot-upload/),就足够说明问题了.所以敏感内容到底交给谁,不能只看"官方"和"第三方"的招牌.

## 买之前,先把数字翻译成人话

看中转的价格,第一步不是比较谁的"倍率"小,而是先问清楚 **1 元人民币能买多少站内余额,余额是什么单位,倍率又乘在哪个基准价上**.有的写"1 元=1 刀=1 余额,0.03 倍率",有的写"1 元=0.2 刀=0.2 余额,0.15 倍率".假设两家都以官方 API 价目表中同一笔 1 美元的用量为基准,A 家扣 0.03 余额,也就是约 0.03 元;B 家扣 0.15 余额,但 1 元只买到 0.2 余额,实际就是约 0.75 元.不同模型、输入输出和缓存可能还各有倍率,所以宣传页只甩一个"0.03"或"0.15",却不说单位和扣费公式,我就不会下单.

定价不一定非得追求最低,自己觉得值就行.真正怕的是,有人拿订阅额度反代,却照着正式 API 原价卖,还把长上下文翻倍、缓存创建费一并算进去.尤其是 Codex 相关模型,官方的 [API 价目表](https://developers.openai.com/api/docs/pricing)和 [Codex 订阅额度](https://learn.chatgpt.com/docs/pricing)本来就是两套账,后者也没有单独的缓存写入收费.如果卖的是订阅反代,至少先把上游和扣费规则说清楚,别把 API 账单里的项目不声不响地搬过来.

价格看明白后,我还会先找售后入口:有没有联系方式或频道,出错、扣费争议和退款要找谁.先小额充值,在自己常用的时段试,比一次买一大包然后祈祷它稳定靠谱得多.

最后再看上游本身.用同一类任务测首字速度和后续流式输出,在自己常用的时段多试几轮;重复发送有稳定前缀的请求,看看缓存是否真的按宣传命中,号池切换时会不会忽快忽慢.想判断有没有掺水,可以用不联网的问答和一次成型的小作品,与自己信得过的渠道做盲测,再看看模型指纹和实际响应.别光靠接口名称相信它是什么模型,也别只凭一道题就宣布抓到了假货.

## 最后才是接入 Codex

确认自己买的是什么之后,接入反而不是最难的一步.[CC Switch](https://github.com/farion1231/cc-switch)、[Codex++](https://github.com/BigPizzaV3/CodexPlusPlus)或者其他同类工具,都可以帮你管理供应商配置和切换入口.其中 Codex++ 是我一直参与维护的开源项目.

实际配置时,先确认服务给的密钥和接口地址对应哪种协议、支持哪些模型与工具能力,再用小任务试通,核对一次真实扣费.一个地址能返回聊天文字,不代表它就完整支持 Codex 的工具调用、长任务和上下文处理;能接上,与适合长期拿来开发,中间还隔着稳定性、账单和数据边界.

说到底,别一上来就问哪家倍率最低.先搞懂一块钱到底买到了多少可用额度,你把代码交给了谁,再谈怎么让 token 一直够用.
